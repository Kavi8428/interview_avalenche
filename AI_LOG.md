# Part C: AI & Research Log

This log lists how I actually used AI and research on this assessment. I used **Google Antigravity** to generate most of the code and documentation drafts, and **Claude** to explain the task and review my work.

---

## Moment 1: Building the plugin with Google Antigravity
- **What I asked:** I gave Antigravity the Gift Wrap requirements from the assessment.
- **What I got back:** A working first version of the plugin. It included:
  - the HPOS compatibility declaration (`before_woocommerce_init` plus `FeaturesUtil::declare_compatibility`), which I did not ask for; the AI added it itself
  - validation of the 100-character limit in `woocommerce_add_to_cart_validation`
  - a fallback truncation to 100 characters when the message is stored
  - the fee calculation on `woocommerce_cart_calculate_fees`
- **What I did with it:** Kept the HPOS declaration and both the validation and the truncation fallback, since both came from the AI and behave sensibly. I tested the result in a WordPress sandbox. I did not rewrite these parts myself.

## Moment 2: Understanding the assessment with Claude
- **What I asked:** "explain and guid me step by step what can i do" (with the assessment PDF attached).
- **What I got back:** An explanation of Parts A to D, the Part A bugs, a suggested list of WooCommerce hooks, and a checklist of deliverables.
- **What I did with it:** Used it to plan the work and choose the WooCommerce track. I used the hook list as a starting point.

## Moment 3: Claude review found an insecure case in the AI-generated plugin (AI answer was insecure)
- **What I asked:** I uploaded my plugin and documents and asked "Is this correct?".
- **What I got back:** A review. The most important finding was that the plugin did not check **on the server** that a product is giftable. Anyone could send `wc_add_gift_wrap=yes` for a non-giftable product and get the fee and gift data added. Other findings:
  - the plugin file had no `Plugin Name` header
  - block checkout might not create the packing order note
  - my testing and AI log made claims I had not verified
- **What I did with it:** Fixed the issues. I added a server-side `is_giftable()` check in validation, in add-to-cart and in the fee loop, added the plugin header, added a Store API hook for the order note, and then uploaded the new version and asked "Is it ok now?". The re-review confirmed those fixes.

## Moment 4: The `unique_key` line (AI-generated code that was wrong)
- **What I asked:** This line was in the code generated by Antigravity. I did not write it and I did not question it.
- **What I got back:** The code added `$cart_item_data['unique_key'] = md5( microtime() . wp_rand() )`, which forces a new cart line every time.
- **What I did with it:** Claude's review pointed out that WooCommerce already includes `$cart_item_data` in the cart item hash, so different messages already create separate lines, and that the random key stops identical wrapped items from merging. I did not find this myself. I removed the line after the review.

## Moment 5: Drafting the documents with AI
- **What I asked:** I used AI to draft `REQUIREMENTS.md`, `TESTING.md`  scripts.
- **What I got back:** First drafts of the requirements questions, the test table and a recording outline.
- **What I did with it:** Used them as drafts. After the Claude review I corrected claims that I had not verified (for example in the testing and AI log files).
